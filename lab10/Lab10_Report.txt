2. Hardware Utilization:
Look at the output of your Live Dashboard. Explain how the OS successfully ran Workload A (LLaMA Training), Workload B (Preprocessing), and Workload C (Inference) AT THE SAME TIME without crashing. Why didn't they block each other?

Answer:
ระบบสามารถรัน Workload A, B, และ C ได้พร้อมกัน (Concurrency) โดยไม่บล็อกกัน เพราะลักษณะของความต้องการทรัพยากรแยกจากกันอย่างลงตัวและไม่เกินเพดานของฮาร์ดแวร์:
1. ด้าน RAM: ทรัพยากรทั้งหมดมี 64GB งาน Workload A ใช้ 40GB, Workload B ใช้ 16GB, และ Workload C ใช้ 2GB รวมเป็น 58GB ซึ่งยังคงเหลือ 6GB ในช่วงพีค ทำให้ไม่มีงานใดติดคอขวดด้านหน่วยความจำ
2. ด้าน GPU: 
   - Workload A ต้องการประมวลผลโมเดลขนาดใหญ่ จึงครอบครอง GPU 0, 1, 2
   - Workload B เป็นงาน Preprocessing ที่เป็น CPU/IO-Bound จึงขอ 0 GPU และเข้าทำงานบน CPU ได้ทันทีโดยไม่ต้องรอคิว GPU
   - Workload C ต้องการเพียง GPU เดียว จึงเข้าไปครอบครอง GPU 3 ซึ่งเป็นตัวเดียวที่ว่างอยู่
ด้วยการออกแบบ Resource Allocation แบบแยกแยะประเภทงาน ทำให้เกิด Hardware Utilization สูงสุด (GPU 100% busy, RAM ใช้ไปเกือบเต็ม) โดยไม่มีงานใดต้องบล็อกรอซึ่งกันและกัน
