2. I/O Bound Concept:
If an Operating System is described as being "I/O Bound" during a task, what does that actually mean for the CPU? Is the CPU at 100% usage or is it mostly idle? Why?

Answer:
ภาวะ "I/O Bound" หมายความว่า อัตราความเร็วในการทำงานของทั้งระบบถูกจำกัดด้วยความเร็วของอุปกรณ์ I/O  เพราะ CPU และ RAM ทำงานได้เร็วกว่าหน่วยเก็บข้อมูลหลายพันถึงล้านเท่า

สำหรับ CPU ในสภาวะนี้ CPU จะ "ส่วนใหญ่ไม่ได้ทำงานหรืออยู่ในสถานะ Idle " ไม่ได้แตะ 100% เพราะ Process ที่รันอยู่ต้องรอข้อมูลที่อ่าน/เขียนจากดิสก์ ส่งผลให้ Process ถูก OS ย้ายไปอยู่ในสถานะ "I/O Wait" หรือ Blocked state เพื่อรอคอย Hardware I/O ทำให้ CPU ไม่มีงานคำนวณและต้องนั่งรอเฉย ๆ

3. AI Industry Connection (Phase 3):
Explain why storing an AI image dataset as 1,000,000 separate `.jpg` files causes high I/O overhead and GPU starvation compared to packing them into a single sequential binary format (e.g., TFRecord, WebDataset, or HDF5).

Answer:
การเก็บเป็นไฟล์แยกขนาดเล็ก 1,000,000 ไฟล์ ก่อให้เกิดปัญหา
1. High OS Overhead: ในทุก ๆ 1 ไฟล์ OS ต้องเสียเวลาค้นหา Inode / Metadata, ตรวจสอบสิทธิ์การเข้าถึงไฟล์ (File permissions), ทำ System Calls เปิด (open) และปิด (close) ไฟล์ซ้ำ ๆ ถึง 1 ล้านรอบ รวมถึงเกิด Random I/O Lookup บน Storage Block
2. GPU Starvation: GPU มีขีดความสามารถในการคำนวณสูงมาก แต่เนื่องจากการอ่านไฟล์ย่อยติดคอขวดที่ I/O ทำให้ Pipeline ส่ง Batch ข้อมูลไปยัง VRAM ช้ากว่าความเร็วที่ GPU ประมวลผลได้ GPU จึงต้องอยู่ในสถานะ Idle  รอข้อมูลจาก Disk

การรวมเป็นไฟล์ Binary ต่อเนื่องขนาดใหญ่ไฟล์เดียว  ทำให้ OS ทำการเปิดไฟล์เพียงครั้งเดียวและอ่านข้อมูลแบบ Sequential I/O ทำให้ช่วยลด System Call และ Metadata Lookup ทั้งหมดลง ทำให้ดิสก์สตรีมข้อมูลป้อนเข้า Memory และ GPU ได้อย่างต่อเนื่องเต็มประสิทธิภาพ
